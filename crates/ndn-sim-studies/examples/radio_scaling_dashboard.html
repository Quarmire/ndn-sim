Named-Data Radio — What Scales, What Codes

Two axes where the broadcast named-data radio's behaviour actually bends: network size (3→100 nodes, uncoordinated access over the real collision model) and network coding (F1 end-to-end FEC vs F2 in-network recode vs F3 COPE). Every point is seed-averaged from the real ndn-sim RadioBus + energy model.
Network size — contention & the listen tax

Channel throughput collapses

Successful (uncollided) airtime as a fraction of the channel. Uncoordinated access peaks early, then congestion collapse — the classic ALOHA curve, on the real medium.

Delivery falls as collisions rise

Per frame×receiver. As more nodes contend, the two curves cross and delivery caves — density, not distance, is the limit here.

The listen tax is a monitor-mode artifact — and it widens with N

Host-CPU energy per node. A promiscuous host processes every neighbour's frames, so its cost grows with the network; a hardware name-filter wakes only for the node's own subscription, staying flat. The shaded gap is what the filter offloads — the doctrine's §3.1 claim, now a curve.

Network coding — F1 vs F2 vs F3

2-hop delivery cost — recode pulls away

Transmissions to deliver a K=12 generation over source→relay→consumer, both hops lossy. F2 recodes at the relay (repairs hop-2 locally); F1 parity is minted at the source, so it re-crosses both hops; forward has no coding at all.

F3 · COPE inter-flow gain

Two flows crossing a relay; it XORs one packet from each into a single broadcast both next-hops decode via overhearing. Savings rise with flow balance toward the 2→1 ceiling.
